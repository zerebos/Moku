# Android

Moku's Android app is built with [Capacitor](https://capacitorjs.com), wrapping the exact same
adaptive Svelte frontend the desktop (Tauri) app uses. The desktop builds stay on Tauri; only the
mobile shell is Capacitor.

## What's different on mobile

The Android app does **not** run a Suwayomi-Server in the background. It expects to connect to an
**existing, remote** Suwayomi instance — set its address under **Settings → General → Server URL**
(for example `http://192.168.1.10:4567`).

Desktop-only features are automatically hidden on mobile because the platform layer reports them as
unsupported. `detectAdapter()` (`src/lib/platform-adapters/index.ts`) selects `CapacitorAdapter`
when `window.Capacitor` is present, and that adapter only advertises `biometric-auth` and
`filesystem`. So the following are hidden/disabled:

- Bundled/auto-started Suwayomi server
- System tray and custom window chrome
- Discord Rich Presence
- In-app updater

Biometric app-lock works on Android through `capacitor-native-biometric`.

### Networking (CORS + cleartext)

Two things make talking to a remote Suwayomi server work from the Android WebView:

1. **CapacitorHttp** is enabled in `capacitor.config.ts`, which patches `window.fetch` to issue
   requests through the native HTTP stack. This is how the GraphQL API calls avoid the WebView's
   CORS restrictions.
2. **Cleartext traffic** is enabled (`android:usesCleartextTraffic="true"` in the manifest, plus
   `allowMixedContent`) so plain-`http://` LAN servers — and the `<img>` requests for pages and
   thumbnails — are not blocked. If you only ever connect over HTTPS you can remove this.

> Known limitation: multipart uploads (e.g. installing an extension `.apk` from a file) and request
> cancellation go through the patched fetch and may behave differently than on desktop.

## Project layout

- `capacitor.config.ts` — Capacitor app id/name, `webDir: dist`, CapacitorHttp + cleartext.
- `android/` — the native Android project, **committed** so builds are reproducible and the manifest
  customization persists. Generated pieces (`app/src/main/assets/public`, `capacitor.config.json`,
  `capacitor-cordova-android-plugins/`) are git-ignored and regenerated by `cap sync`.
- `build:android` (in `package.json`) runs `MOKU_TARGET=capacitor vite build`, which builds the
  static frontend with the Capacitor plugin JS bundled in (see `vite.config.ts`).

## Building locally

**Prerequisites:** Node + pnpm (see the [main dev setup](../README.md#development)), JDK 21 (required
by Capacitor 8's Android module), and the Android SDK (Platform Tools, `platforms;android-36`,
`build-tools;36.0.0`). Android Studio is the easiest way to get these.

```bash
pnpm install

# Build the web assets and copy them + plugin config into android/:
pnpm cap:sync

# Open in Android Studio to run on a device/emulator:
pnpm cap:open

# …or build a debug APK from the CLI:
cd android
./gradlew assembleDebug
```

The APK is written to `android/app/build/outputs/apk/debug/app-debug.apk`.

If you change frontend code, re-run `pnpm cap:sync` before building so the native project picks up
the new assets. `pnpm cap:run` chains sync + `cap run android` for a connected device.

## CI

`.github/workflows/build-android.yml` installs the Android SDK, runs `pnpm cap:sync`, builds an
**arm64-and-friends debug APK** with Gradle, and uploads it as a workflow artifact. Trigger it from
the Actions tab (`workflow_dispatch`).

### Signed release builds

The debug APK is signed with the shared Android debug key — fine for testing, not for distribution.
For a release:

1. Create a keystore and add a `signingConfigs`/`release` block to `android/app/build.gradle` (see
   the [Capacitor signing docs](https://capacitorjs.com/docs/android/deploying-to-google-play)).
2. Build:
   ```bash
   cd android
   ./gradlew assembleRelease   # APK
   ./gradlew bundleRelease     # AAB for Play Store
   ```

To automate this in CI, store the keystore and passwords as repository secrets and inject them into
the Gradle build.
